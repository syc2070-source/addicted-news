ⓐ 소스 읽기 동시 4: crawlOneSource 를 둘로 나눔.
   - readSource(동시 4): 피드 가져오기·해석 + 항목별 네트워크 일(기존 기사 확인 읽기 · 구글 링크 풀기 · 원문 추출).
     이번 실행 공유 상태(seenTitles·묶음 기억·집계·DeepSeek)는 건드리지 않음.
   - judgeSource(하나씩 · 목록 순서): 이번 실행 중복 → 묶음 상속 → DeepSeek 관문 → 후보. 판정 순서·결과는 읽기가 끝나는 순서와 무관.

   - 달라진 점 하나: 이번 실행 「같은 제목」은 판정에서 빠지지만, 다른 소스의 같은 기사도 읽기 단계에서 원문 추출을 한 번 더 할 수 있음
     (네트워크 몫만 · 저장·판정 결과 같음). 같은 소스 안 같은 제목은 읽기에서도 건너뜀.

정직 표기 · 지켜볼 것
1) 새 수집기 본체(읽기/판정 분리)는 단위 시험·형 검사만 거침 — 실제 피드·DB 로 돈 적 없음. 10-14 12:00 runs 에서 progress·timeouts·broadcastChannelsRead 확인 필요.
2) 구글 링크 풀기가 이제 동시 최대 4 갈래로 news.google.com 에 감(옛날 1). 429 가 나면 urlResolveFail 이 늘고 원문 추출이 줄어듦 → runs 의 후보 수로 봄.
3) 고유명사 규칙 문턱 0.25 는 지시(0.35)에서 덧붙인 값 — 1000건 안 오묶음 0 이지만 국감 철 의원실 자료 기사처럼 같은 기관 둘이 겹치는 다른 사건이
   늘 수 있음. 오묶음이 보이면 ENTITY_RULE_ON=false 한 줄.
4) 순환으로 「선호 매체 먼저」 정렬 효과가 날마다 바뀜(■1ⓒ).
5) SAMHSA 를 비활성 → 활성(막힘 · 월 1회)으로 바꿈. 매달 1일 403 한 번이 로그에 남되 실패 피드 목록에는 안 들어감.
